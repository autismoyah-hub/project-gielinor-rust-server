# Cinderworks normal-action acceptance tools

These Python controllers consume the opt-in client adapter in `docs/tower/client-validation.patch`. The native window and headless example both use the same `ClientState` action encoding and real loopback server. No desktop input, focus activation, save editing, item spawning or world mutation is used.

Use only an isolated server, disposable accounts, owned action directories and private output directories. Apply the ten-commit client patch to its documented baseline, build the native binary and `tower_actions` example, then set `TOWER_ACTION_DIRECTORY` when launching either client. Supply its cache path, loopback address, username, password-file path and public-key path through the client's existing launch arguments. The server's normal first-login registration path creates a fresh profile; a pre-created account without an initial logout is intentionally rejected by authentication.

A new action directory needs an initial `command.txt` containing `1 observe`. Commands are sequence-numbered and atomically replaced. Receipts acknowledge dispatch only. Every scenario additionally waits for server-delivered position, items, messages or journal state. Cache onOp listeners can submit actions without a direct IF_BUTTON mask; the controller sends such a request once and verifies its outcome.

Run `services.py --directory ACTIONS --output EVIDENCE --onboard --gate-check` for ordinary appearance/experience choices, plaque, prerequisite rejection, mining, smelting, forging, wielding, net fishing, item-on-range cooking, creature combat, bones pickup and item-on-altar offering. `--stage kitchen` or `--stage altar` resumes only a deliberately interrupted route with its actually earned items. Food consumption includes its normal action delay before a pickup retry.

Run `recovery.py` with the same directory/output options to intentionally stand in real Imp vents until lethal damage, then assert sanctuary rescue preserves equipment, items and services without granting an unlock. This is an intentional defeat scenario; it does not accept a retreat as victory.

Use Python 3.12 or newer. Run `guardian.py imp` and then `guardian.py warden` with the same directory/output options. The bounded controller reads real smoke/eruption graphics, moves, eats and searches coolant barrels. It records authoritative phase messages and victory. `--label` distinguishes attempts; failures remain failed. A victory stops combat with normal movement out of the court. Pattern geometry is deterministic; ordinary combat rolls vary, so bounded timeouts can fail and must never be silently classified as success.

Run `claim.py --directory ACTIONS --output EVIDENCE --full-pack` after the first victory to fill the pack by normal fishing, prove atomic claim denial, drop two raw shrimp, claim exactly 500 coins plus a beer, and prove repeated searches pay nothing. Replay uses `--coins 25` without `--full-pack`. The claim message is emitted only after account-worker save acknowledgement. Retain before/after observations across real disconnect/relogin and restart separately.

All IDs and coordinates are specific to the pinned OSRS239.1 cache and this authored origin. Logs and actual native framebuffer captures remain private. These scripts cannot replace final visual review or be used to claim acceptance when an assertion fails.

Use `--native-frames` only when the attached client actually renders a native window. Headless scenarios record observation sequences, not images. `tour.py` walks all authored courts with normal movement and bounded retries for wandering actors. `exit_return.py` waits for complete region rebuilds and asserts exact inventory, equipment, XP and journal preservation. Court-local hazard filtering allows independent encounters without reacting to another court's smoke.

Inventory observations can omit empty trailing slots. Controllers count occupied slots against the actual 28-slot capacity, and open the inventory panel before waiting for visible Wield/Use/Drop actions. A failed replay Imp attempt exhausted food under native frame stalls; it remains a failed diagnostic. Four-tick telegraphs preserve a readable reaction window, and safe adjacent Imp attacks reduce unnecessary idle time. New supplies always come from ordinary fishing/cooking.

`intro.py` verifies normal character choices and the authored guide before the plaque, with no implicit tool or run grant. `gateway_lock.py` is an optional Windows regression on an owned disposable native session: it briefly holds a read-only snapshot handle, performs one normal axe/dagger swap and verifies recovery. The adapter retries observation writes without replaying gameplay actions; `inspect` explicitly requests large diagnostic text dumps, while ordinary combat observations remain lightweight.

Apply the client mailbox with `git am --keep-cr client-validation.patch` from the pinned baseline. The client baseline contains CRLF blobs; the patch is intentionally stored with `-text` so Git cannot normalize its context bytes. The current ten-commit patch is checked through a separate index to reproduce the exact tested client tree.

Visual production tools: `visual_walkthrough.py` captures fourteen spaces at yaw 0/4096/8192/12288 (16384 units per turn); it requires genuine native BMP output and never treats headless observations as images. Raw frames and scene-object CSV stay local. `inspect` now exports read-only scene provenance in native and headless modes. Guardian scenarios require the current ten-patch client and normal chat UID observations, select the displayed aggressive style, evade first, and Search genuine rainwater barrels only from safe adjacent tiles. Strength is earned exclusively from normal hits. The inside exit is now (10432,124). No source timing, damage or reward assertions are weakened.

`message_events.uid` identifies real normal-chat messages. Its `cycle` is the UI clock; `state.cycle` and graphic `start` use actor time. Do not compare those clock domains. `guardian.py --require-coolant` first demonstrates a stationary adjacent interruption and requires its new UID before resuming melee. It never chases a distant interaction through a warning.

`restoration.py` compares five, six or eight explicit expected landmark IDs with real ClientState scene objects. It never mutates scene state and only claims native frames when the raster file exists. The current foundry-bank source defaults to eight landmarks; `services.py --landmarks 6` is reserved for an explicitly pinned predecessor binary. Current acceptance controllers still pass `--landmarks 8` explicitly. `services.py --scene-checks --coolant-lesson` validates the harmless real Search lesson and each service's visible response. `--order kitchen-first` exercises an alternate legal preparation order; `--native-frames` captures the journal view after each response. The master hearth stays cold until Warden victory, then paid first-clear history keeps it lit in replay.

`guardian.py --style accurate` selects the actual displayed dagger Stab button through Combat Options, training Attack from normal hits; the default aggressive style selects Lunge and trains Strength. A longer explicit scenario timeout changes only the controller bound, never world tick timing. Native journal captures wait for the real text after UI rebuild, rather than interpreting a transient blank as lost progress.
